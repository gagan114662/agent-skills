# The one-prompt customer pipeline

The brief for ipop is simple: type your domain, get a useful customer-acquisition engine, and keep going until the customer goal is hit. The product is not there yet, so this guide names the pipeline the build is moving toward.

## 1. Read the business

The first action is the domain scrape: homepage, pricing, proof, audience clues, conversion paths, and trust gaps. The output should be an ideal customer profile with source evidence, not a vibe summary.

## 2. Choose the fastest honest wedge

The fleet should pick one reachable buyer segment, one offer, and one channel where a useful first touch can happen safely. This is where ipop must avoid generic marketing advice. A founder needs the next ten prospects, not a forty-slide strategy deck.

## 3. Produce assets before asking for setup

The first visible artifact should be useful without integrations: a teardown, a comparison page, a guide outline, an email draft, or a landing-page patch. Setup should unlock shipping, not block seeing value.

## 4. Route risk through approvals

Money needs explicit approval. Public work and outreach need receipts, rollback, policy checks, and workspace controls. The product should make this distinction obvious so autonomy feels useful instead of reckless.

## 5. Keep the loop alive

The customer goal is not met when a draft exists. The loop continues through publish, measure, learn, revise, and the next action. The work feed should show what agents did, what evidence they used, and what changed because of the result.

## What to watch for

If any step becomes an empty shell, the system is no longer a marketing engine. Good ipop output names the customer, the channel, the artifact, the approval state, and the receipt.
